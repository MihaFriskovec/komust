Rehearse the Public Release contract

Question: can one checkpointed local command carry an already-qualified candidate through Central, the Plugin Portal, public verification, the tag, and an immutable GitHub Release—without losing artifact identity, leaking credentials, replaying an irreversible step, or guessing after an ambiguous response?

Planning instrument, not release tooling. No registry, credential, tag, or GitHub operation is performed by this file. The pure state machine below is the proposed contract; the page exists only to push it through awkward cases.

Contract

Proposed command surface

Invariants enforced on every invocation
  • The explicit checkpoint path is mandatory; it is atomically rewritten after one successful transition.
  • The clean checkout, fixed version, commit, manifest digest, SBOM digest, staged JAR/POM bytes, coordinates, and checkpoint must agree.
  • Ambiguous responses stop the command. Only reconcile may discover whether the remote transition happened.
  • No secret value is written to the checkpoint, arguments, files, logs, Gradle properties, keyring, or shell history.
  • After any public coordinate appears, the version is consumed. A definitive failure can only finalize an Incomplete publication.
  • --dry-run refuses secret-bearing environment variables and remote writes; it produces a simulated checkpoint ending in Dry-run complete.
